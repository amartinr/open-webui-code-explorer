## 1. Context

The repo generates Open WebUI Tools (self-contained scripts in `dist/`) from
`common.py` + templates. When the user presses **Stop** in Open WebUI, the
tool coroutine receives a `CancelledError` and aborts. `CancelledError`
inherits from `BaseException`, not `Exception`, so it passes intact through
any intermediate `except Exception` in the backend and reaches the tool.

## 2. Problem

`run_allowed` (common.py) runs git via
`asyncio.to_thread(subprocess.run, ...)`. When the awaiting coroutine is
cancelled:

- The executor thread cannot be killed from outside: git keeps running in the
  background until it finishes or hits its timeout (clone 600 s,
  fetch/pull 120 s, misc 30 s).
- The user believes the operation was aborted, but git continues (e.g. a pull
  may complete in the background).
- A cancelled clone skips the existing partial-clone cleanup, leaving the
  `<owner>/<name>` namespace blocked for later attempts (`repo already
  exists`).
- The only backstop today is the timeout; cancellation does not kill the
  process.

## 3. Change 1 — `run_allowed` (common.py)

Rework subprocess execution so it is cancellable and controllable:

1. **Async spawn of the real process:** instead of delegating to a thread,
   create the process with the async subprocess API, capture its output
   pipes, and await its completion with the standard mechanism that avoids
   blocking on full pipes (i.e. `asyncio.create_subprocess_exec(...,
   stdin=PIPE, stdout=PIPE, stderr=PIPE, env=_headless_env())` +
   `await proc.communicate(input=...)`). The coroutine then awaits the real
   process, so both cancellation and timeout act on it directly.
   - `communicate()` drains stdout/stderr concurrently: no pipe-deadlock.
   - `run_allowed` is already async and is called inside an event loop
     (Open WebUI backend; the test suite runs under pytest-asyncio's auto
     mode), so `create_subprocess_exec` is safe to use.
2. **Kill helper:** extract a routine that kills a process in stages:
   graceful terminate (`proc.terminate()`) → wait a short grace period
   (e.g. `asyncio.wait_for(proc.wait(), 1)` with the timeout absorbed) → if
   still alive, kill hard (`proc.kill()`) → await its reaping (`proc.wait()`).
   Never leave zombies.
3. **Timeout:** on expiry, use that helper to kill the process and return the
   `Timed out:` error with today's exact format and semantics (the existing
   timeout tests must stay green). Implementation: wrap the communicate in
   `asyncio.wait_for(..., timeout)`, absorb the `TimeoutError`, kill, then
   raise `ToolError(..., kind="timed_out")`.
4. **Cancellation:** explicit `except asyncio.CancelledError:` handling that
   (a) kills the process with the same helper and (b) **re-raises** so the
   cancellation keeps propagating as a `BaseException`. Never swallow it,
   never convert it into a result or an `Error:` string.
5. **Contract intact:** keep the binary allow-list, the executable
   resolution (`shutil.which`), the fixed headless env, the
   `CommandResult(stdout, stderr, returncode)` shape, and BOTH the `text`
   (locale-decoded str) and `text=False` (bytes) modes, AND the `input`
   kwarg added by E11 (`git cat-file --batch` feeds rev:path lines via
   stdin) — the rework must keep `text=False, input=<bytes>` working.
   Decoding/encoding behaviour must match the current implementation
   (`text=True` decoded by the process locale; `text=False` raw bytes).

## 4. Change 2 — `_clone_repo` (templates/repos.py.tpl)

Protect the clone and the post-clone checkout:

1. Wrap the clone invocation (and the post-clone checkout if applicable) in
   cancellation handling.
2. On `CancelledError`: run the existing partial-clone cleanup
   (`_cleanup_failed_clone(root)` — removes the partial dir when it is not a
   valid git repo) and **re-raise**.
3. Result: a cancelled clone leaves no partial directory blocking
   `<owner>/<name>`; a second `cexp_clone_repo` on the same repo succeeds.

## 5. Tests to add

- **Kill helper (unit):** spawn a real slow child directly with
  `asyncio.create_subprocess_exec("sleep", "60")` (the helper is
  low-level; it does not go through `run_allowed`'s allow-list), run the
  kill routine, and assert the process is gone (`proc.returncode is not
  None`), no zombie.
- **Cancellation (integration):** run `run_allowed` on a genuinely slow git
  (e.g. `git log --all` over a repo with ~1-2k commits built in the test),
  cancel the task (short `asyncio.wait_for` or explicit `task.cancel()`),
  and assert: the `CancelledError` propagates (`task.cancelled()` is True;
  NOT converted into `Error:`) and the child process is dead (no lingering
  git child after the kill grace).
- **Timeout regression:** the existing timeout test (monkeypatched
  `subprocess.run` raising `TimeoutExpired`) must be updated to the new
  implementation if it no longer applies, or kept equivalent — the
  observable contract (`Timed out:` with the same message) stays.
- **Cancelled clone (integration):** cancel a slow `cexp_clone_repo`
  (or simulate by cancelling the underlying `run_allowed`), then assert no
  partial directory remains and a second `cexp_clone_repo` succeeds.
- **Full regression:** headless env, text/bytes modes (incl. the E11
  `input`/`cat-file --batch` path), and the rest of the suite (389 tests +
  new).
