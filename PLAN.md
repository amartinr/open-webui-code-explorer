## 1. Design decision (already made — do not re-litigate)

**Extend the existing tools with optional selector parameters; do NOT add new
tools.**

| Tool | New parameter | Default | Meaning |
|---|---|---|---|
| `cexp_read_file` | `ref: str` | `None` | Read the file as it exists at a branch/tag/commit; `None` = working tree. |
| `cexp_list_files` | `ref: str` | `None` | List the files present at a ref; `None` = working tree. |
| `cexp_compare_commits` | `context: int` | `None` | Unified-context lines (`-U N`); its existing `path` already narrows a diff to a single file. |

Rationale (DESIGN.md §10): `ref` and `context` are *selectors*, not *dispatch*
parameters — exactly like the existing `start`/`end`/`path`/`filter`/`type`.
Separate `*_at_ref` tools would duplicate the line-range/truncation/
binary-detection logic and add redundant tool names. The change is purely
additive and backward-compatible: existing calls keep working.

## 2. New shared helper: `validate_ref` (`common.py`)

Add to `common.py` (inline-safe: stdlib only, no module-level side effects):

- A module-level regex alongside the existing ones:
  ```python
  _REF_RE = re.compile(r"^[A-Za-z0-9_][A-Za-z0-9._/+-]*$")
  ```
- A function:
  ```python
  def validate_ref(ref: str) -> str:
      # returns ref unchanged, or raises ToolError naming the offending ref
  ```

Reject (raise `ToolError` with a `cause:` line naming the ref) when **any** of
the following hold:

1. Empty, or contains any whitespace.
2. Starts with `-` (option injection).
3. Contains `:` (guards `ref:path` revision syntax / protocols).
4. Contains `..` (covers `..` and `...` revision ranges).
5. Does not match `_REF_RE` — this rejects `~ ^ * ? [ ] { } @ \` and a leading
   `.` (the first char must be `[A-Za-z0-9_]`).

Accept: branch names (incl. slash-containing like `release/v1.0.0`), tags
(incl. `v1.0.0-rc.1+build.5`), short/full commit hashes, and `HEAD`.

Deliberately **reject** revision expressions (`HEAD~1`, `main^`, `main@{...}`).
Do not try to support them; document this in the tool docstrings where relevant.

## 3. Apply `validate_ref` to every ref-accepting tool (hardening)

This closes pre-existing option-injection gaps (e.g. `cexp_show_commit(commit=
"--help")`). Replace the ad-hoc empty/whitespace checks with `validate_ref`:

- `templates/repos.py.tpl` — `cexp_clone_repo`: validate `ref`. Call it before
  the `ref == "release"` special case is fine (`"release"` passes validation);
  or validate only the non-`"release"` path — either is acceptable, but the
  raw user `ref` must never reach `git checkout` unvalidated.
- `templates/commits.py.tpl`:
  - `cexp_list_commits`: validate `ref_a`/`ref_b` when provided (after which
    `f"{ref_a}..{ref_b}"` is safe).
  - `cexp_show_commit`: validate `commit` (replaces the current empty check).
  - `cexp_compare_commits`: validate `ref_a`/`ref_b` (replaces the current
    empty check).

## 4. `cexp_read_file` + `ref` (`templates/files_search.py.tpl`)

Add `ref: Optional[str] = None` to the public signature and to the docstring as
a **single-line** `:param ref:` entry (Open WebUI parses docstrings line-by-line,
§9.6). Update the prose to give an example using a released tag + line range.

Implementation (`_read_file`):

- `ref is None` → existing working-tree read, unchanged.
- `ref` given:
  1. `ref = validate_ref(ref)`.
  2. Resolve/validate `path` with `resolve_path` (path need not exist on disk;
     only inside the repo root).
  3. Size guard: `git -C <root> cat-file -s <ref>:<path>` → if `> MAX_READ_BYTES`,
     raise the same "file too large" `ToolError` as the working-tree reader.
  4. Fetch the blob **as bytes** via `git -C <root> cat-file blob <ref>:<path>`
     using the new bytes-capturing runner (see §5 below).
  5. Reuse the existing binary/UTF-8 detection on the bytes — `_scan_encoding`
     (whole-file incremental UTF-8 decode) — with **identical** rejection
     messages ("binary file not supported", "not a UTF-8 text file").
  6. Reuse the existing line-range math: `start`/`end` (1-based, clamp to EOF,
     empty-file → `""`, `start > total` error, `end < start` error,
     `MAX_INLINE_LINES` streaming) and the same truncation markers.

Error distinction (test this): a bad ref → `Error:` with `cause:` naming the
ref; a valid ref whose path is missing at that ref → `Not found:`.

## 5. Bytes capture: extend `run_allowed` with a `text` flag (`common.py`)

`run_allowed` currently decodes subprocess output with the process locale
(`text=True`), which is not reliable for non-ASCII file content and discards
the raw bytes needed for binary/UTF-8 detection. **Do NOT add a second
function.** Extend the existing one with a keyword-only flag:

```python
async def run_allowed(argv: list[str], timeout: int, *, text: bool = True) -> CommandResult
```

- `text=True` (default): unchanged behaviour — stdout/stderr are `str`,
  decoded with the locale. All existing call sites keep working untouched.
- `text=False`: stdout/stderr are `bytes` (raw output). Same allow-list check,
  `shutil.which` resolution, `asyncio.to_thread` offload, `shell=False`,
  `timeout`, and `_headless_env()`. `subprocess.run` is called with
  `text=False`; empty output is `b""` (not `""`).

Used by the read-at-ref path: `run_allowed(git_args("-C", root, "cat-file",
"blob", f"{ref}:{path}"), TIMEOUT_SEARCH, text=False)` returns raw bytes, which
are then passed to the existing whole-file UTF-8/binary scan before explicit
`bytes.decode("utf-8", errors="replace")`. This makes ref reads byte-identical
in behaviour to the working-tree reader.

## 6. `cexp_list_files` + `ref` (`templates/files_search.py.tpl`)

Add `ref: Optional[str] = None`, with a single-line `:param ref:`.

- `ref is None` → existing `os.walk` path, unchanged.
- `ref` given:
  1. `ref = validate_ref(ref)`.
  2. Validate `path` (if provided) with `resolve_path` for traversal safety;
     do **not** require it to exist on disk.
  3. Run `git -C <root> ls-tree -r --name-only <ref>` (newline-separated).
     Consider `-z` (NUL-separated) via the bytes runner for filenames with
     embedded newlines — optional robustness, not required.
  4. Derive directories from file paths (git tracks no empty directories).
  5. Apply the existing `filter`, `type`, `max_depth` (computed from path
     depth), and `max_results` cap in Python, sorted by path. Return the same
     `{"path", "kind"}` shape.

Document that `type="dir"` reflects *implied* directories (no empty dirs exist
in git).

---

## 7. `cexp_compare_commits` + `context` (`templates/commits.py.tpl`)

Add `context: Optional[int] = None`, single-line `:param context:`.

- Validate both refs with `validate_ref` (§3).
- If `context` given: reject `context < 0`; insert `-U {context}` before the
  refs: `git -C <root> diff [-U N] [--stat] ref_a...ref_b [-- path]`.
- Everything else (three-dot default, `--stat`, `path` narrowing, truncation)
  stays unchanged.
- Docstring: frame `path` as the way to narrow a truncated whole-tree diff to a
  single file, and note it composes with `cexp_read_file(ref=...)`.

## 12. Acceptance checklist (re-check before marking done)

- [ ] Reading a specific file at a released tag with a narrow line range returns
      the exact content from that tag, using only the local clone (no network,
      no working-tree mutation).
- [ ] A whole-tree diff that previously truncated can now be fully inspected:
      the single-file diff shows the complete change, and both sides can be read
      at their respective refs to page through the details.
- [ ] Forbidden refs are rejected with the standard error shape in every tool
      and never reach git unvalidated.
- [ ] Binary and non-UTF-8 blobs at refs are rejected exactly like their
      working-tree counterparts.
- [ ] `build.py` regenerates `dist/` with the new parameters; the full test suite
      is green; the documentation reflects the new surface.
