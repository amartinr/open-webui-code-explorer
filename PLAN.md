Only then Phase 1 (cheap wins), Phase 2 (UX), Phase 3 (new capability). The original draft's "do before any shared deployment" was a *deployment* priority; this is the *implementation* priority.

## Phase 1 — cheap wins (after the security phase)

### E1. `cexp_show_commit(stat: bool = False)` — Commits script

Add `stat` to `cexp_show_commit`.

- `stat=True`: run `git show --stat --format=fuller <commit>` (i.e. commit metadata + file-change summary, **no diff body**). Apply the same `max_lines`/`max_bytes` truncation as the full show.
- `stat=False` (default): current behaviour, unchanged.
- `path=` must compose with `stat=True` (stat limited to that path): `git show --stat --format=fuller <commit> -- <path>`.
- Invalid commit → `Error:` naming the commit (same as today).

**Tests:** stat=True returns the changed-file list and commit subject but not the diff body; stat + path narrows the file list; stat output respects the byte cap; invalid commit errors.

### E2. `cexp_list_commits(first_parent: bool = False)` — Commits script

Add `first_parent` to `cexp_list_commits`.

- `first_parent=True`: append `--first-parent` to the `git log` invocation. This traces the *merge narrative* of a branch, hiding the squashed/merged side-branch commits (the "refac" noise problem).
- Must compose correctly with `ref_a`/`ref_b` ranges and with `path=` (git supports `--first-parent` alongside both).
- `first_parent=False` (default): current behaviour.

**Tests:** in a repo with a merge commit, `first_parent=True` omits commits reachable only via the merged branch and keeps the merge commit itself; range (`ref_a..ref_b`) still correct; `path=` still filters.

### E3. `cexp_search_text(files_only: bool = False, count_only: bool = False)` — Files & Search script

Two mutually-friendly output modes on the existing search.

- `count_only=True`: items are `{"path", "count"}` (number of matches per file), no line matches. Prevails over `files_only`.
- `files_only=True` (without `count_only`): items are `{"path"}` (unique matching files), no lines.
- Both default `False` → current line-match output.
- `context` is ignored when either flag is set (no lines to show); document this in the docstring.
- `case_sensitive`, `path`, `filter` behave exactly as today; `max_results` caps the *file* count in these modes.

**Tests:** count_only counts matches correctly per file; files_only returns unique paths; count_only+files_only → path+count; context ignored in these modes; caps apply to file count.

### E4. `cexp_list_commits`: add `author` and `date` fields — Commits script

Extend the `git log --format` to also emit the author name and a short absolute date (`YYYY-MM-DD`). Items become `{"hash", "subject", "author", "date"}`.

- Author = commit author name (no email; keep output compact).
- Date = `YYYY-MM-DD`; use the **commit date** (`%cd` with `--date=short`).
- Backward compatible: new fields are additive; existing consumers that read `hash`/`subject` keep working (the JSON shape only grows; the current `line.split(" ", 1)` parse becomes a tab-separated parse: `--format=%h%x09%an%x09%cd%x09%s --date=short`, since author names may contain spaces).
- Applies to all three list modes (default HEAD history, `ref_b`, `ref_a..ref_b`); also to `cexp_search_history` (E7) for consistency.

**Tests:** fields present and parse correctly; date is the commit date; caps still applied.

## Phase 2 — UX of the agent (trivial)

### E5. Truncation hint

When any cap truncates output, add a `hint` field so the agent knows how to narrow instead of re-asking:

- Structured (JSON) tools: add `"hint"` inside the `truncated` object, tool-appropriate, e.g. `"use path=/filter= to narrow, or raise the max_results Valve"`.
- Raw-text tools (`cexp_read_file`, `cexp_show_commit`, `cexp_compare_commits`): append a `hint:` line after the existing truncation marker.

Implementation note: extend `json_output(data, max_bytes, hint=None)` and `truncate_output(text, max_lines, max_bytes, hint=None)` in `common.py` with an optional `hint`; tools pass a tool-specific string. Default `None` keeps current output byte-for-byte. A few existing tests assert the `truncated` object or the marker **exactly** (`tests/test_valves.py` `{"shown": 2, "total": 3}`, `TestTruncateOutput.test_line_cap`): update those assertions to the new shape in the same commit (the change is the point of E5).

**Tests:** hint present exactly when truncated; absent when not truncated.

### E6. "Repo not found" errors suggest existing clones

When a tool fails because the repo is not cloned (the `_ensure_repo_exists` path), append to the `cause:` the list of currently cloned repos (from the same enumeration logic as `cexp_list_repos`, capped to avoid huge output, e.g. first 10).

Implementation note: add a shared helper in `common.py` (e.g. `list_cloned_repos(repos_path, limit=10) -> List[str]`, repo names only, sync walk — names suffice for a hint) and use it in `_ensure_repo_exists` (all three templates, deduplicated in the combined script) and in `cexp_list_repos`'s enumeration where practical.

**Tests:** error for a missing repo names the existing clones; behaviour unchanged when the repo exists.

## Phase 3 — new capability (medium effort)

### E7. `cexp_search_history(query: str, path: str | None = None, ref_a: str | None = None, ref_b: str | None = None)` — Commits script

Git pickaxe search: "when was this string/regex introduced or removed?"

- Implementation: `git log -S <query> [-- <path>] [<ref_a>..<ref_b>]` (string literal pickaxe). Use argument-array form; `query` is passed as a separate argument to git (no shell). Validate: non-empty, no NUL, reasonable length cap (e.g. 512 chars); a leading `-` is safe because it is consumed as `-S`'s value, but still reject empty/whitespace-only. Use the E4 format (`--format=%h%x09%an%x09%cd%x09%s --date=short`, not `--oneline`) so the items carry author/date.
- Returns the same `{"hash", "subject", "author", "date"}` items as `cexp_list_commits`, capped by `max_results` with the standard `truncated` metadata.
- Not found → empty `items` array (not an error).

**Tests:** finds the commit that introduced a known string; `path=` narrows to that file; range refs restrict the window; empty result for absent string; refs validated by `validate_ref`.

### E8. `cexp_list_branches(merged: bool | None = None)` — Commits script

- `merged=None` (default): current behaviour (all branches).
- `merged=True`: `git branch --merged` (branches already merged into HEAD) → handy for "is `dev` already in `main`?".
- `merged=False`: `git branch --no-merged`.
- Composes with `remote=True` (`git branch -a --merged` etc.).

**Tests:** merged=True lists only merged branches; merged=False only unmerged; composition with remote works.

### E9. `cexp_remove_repo(repo: str, dry_run: bool = False)` — Repos script

Add the missing lifecycle operation (disk hygiene).

- Resolve root via `resolve_repo_root`; if the directory does not exist → `Not found:`.
- Safety: resolve the target with `.resolve()` and require it to be strictly inside the resolved `repos_path` (same guard style as `resolve_path`); refuse symlinked roots.
- `dry_run=True`: return the path and its on-disk size (bytes) **without deleting**.
- `dry_run=False`: delete the directory tree (`shutil.rmtree`, run inside `asyncio.to_thread`) and return a confirmation with the path.
- No repo (empty/malformed `repo`) → existing `resolve_repo_root` errors (`Error:`).

Note: this is the **14th public tool**. `tests/test_valves.py::test_combined_script_loads_and_discovers_all_tools` asserts the exact 13-tool list; add `cexp_remove_repo` to it in the same commit. `cexp_list_repos`-style naming/`origin`/`size` conventions apply to its JSON output (e.g. `{"repo", "path", "dry_run", "size", "removed"}`).

**Tests:** dry_run does not delete and reports size; real run deletes; missing repo → Not found; symlinked root rejected; path is always `<repos_path>/<owner>/<name>`.

### E10. `cexp_list_repos`: add `size` field — Repos script

- Each item gains `"size"` (bytes on disk for that clone, computed with a Python walk inside `asyncio.to_thread`).
- Keep all existing fields; new field is additive.

**Tests:** size > 0 for a repo with files; format otherwise unchanged.

## Phase 4 — security hardening (executed FIRST; cheap and closes live gaps)

### S1. Re-validate the remote origin before `fetch`/`pull`

- In `_fetch_repo` and `_pull_repo`, before invoking git: read the origin with `_remote_origin(root)` and pass it through `validate_clone_url`. If validation fails → `Error:` and **do not run** fetch/pull.
- Rationale: a tampered `.git/config` (e.g. `remote.origin.url = ext::sh -c '...'`) must never reach git; the strict allow-list currently only guards `clone`.
- A clone with no origin (`_remote_origin` → `""`) fails `validate_clone_url` → `Error:` (git would fail anyway; the message now names the missing origin).

**Tests:** repo whose origin is `ext::…`/`file://` → fetch/pull fail with `Error:` and git is never invoked; valid origin → unchanged behaviour.

### S2. Purge hostile `GIT_*` from the subprocess environment

- In `_headless_env()`, in addition to the 7 overridden keys and the removal of `GIT_ASKPASS`, also **delete** (pop) any of: `GIT_DIR`, `GIT_WORK_TREE`, `GIT_OBJECT_DIRECTORY`, `GIT_ALTERNATE_OBJECT_DIRECTORIES`, `GIT_SSH`, `GIT_SSH_VARIANT`, `GIT_INDEX_FILE`, `GIT_NAMESPACE`, `GIT_COMMON_DIR`.
- Keep the existing overrides (they set the policy); this closes the "env points git at a different repo/ssh binary" gap.

**Tests:** with hostile `GIT_DIR`/`GIT_SSH` set in the environment, git does not use them (mirror the existing `test_git_never_reads_global_config` pattern).

### S3. Optional Valve: host allow-list for `cexp_clone_repo`

- New shared Valve field `allowed_hosts: str = ""` (comma-separated) on the Repos script only (the only script that clones).
- When non-empty, `_clone_repo` rejects any `url` whose host is not in the list; allow exact host match or suffix match on a dot boundary (e.g. `github.com` also allows `raw.githubusercontent.com` only if listed — no implicit wildcard beyond subdomains of a listed host).
- Empty (default) → no restriction (backward compatible).
- Apply after `validate_clone_url`, reusing `urlparse`.

Note: `tests/test_valves.py` currently enforces the **identical** Valves field set across all four scripts (`set(fields) == set(REQUIRED_VALVES)`). Adding `allowed_hosts` to Repos only is a deliberate contract change: update the test so `REQUIRED_VALVES` remains the shared core (`set(REQUIRED_VALVES) <= set(fields)`) and Repos is the one script allowed the extra `allowed_hosts` field.

**Tests:** host in list passes; host outside → `Error:`; empty list = unrestricted; subdomain of listed host allowed; credential rules still enforced.
