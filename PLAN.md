## 1. Context

The toolset is pure prevention without detection: security rejections and
operation failures leave no trace. There is no way to know what was cloned,
when, from which URL, what was blocked, or what failed. This plan adds a
minimum of actionable auditing so an operator can reconstruct the history of
repo operations and see blocked attempts.

The logger `"code_explorer"` already exists (used by `check_binaries` to warn
when git is missing at load). Open WebUI's backend uses Python `logging`
(writes to stdout at INFO by default), but the tool's own stdout is what the
model sees — so audit events MUST go to the logger, NEVER to the tool's
stdout, NEVER via `print`. Audit in the product is opt-in
(`CPTR_AUDIT_LOG_LEVEL=NONE` by default), so this audit is **opt-in via a
Valve**, with **redacted and trimmed** messages, at WARNING and ERROR levels;
CRITICAL is deferred (§7).

## 2. Scope

**Implement now:**
- WARNING (30) events — blocked attempts and handled unexpected conditions.
- ERROR (40) events — operations that genuinely failed.
- INFO (20) — ONE event per successful repo operation (clone/fetch/pull), so
  the basic "which repos get cloned" case is covered. Same mechanism, trivial
  cost.

**NOT implemented now:**
- CRITICAL (50) events — deferred (§7).

**No API change.** One new Valve `audit_log: bool = False` on all four
scripts (the three templates + the combined script's frontmatter in
`build.py`), backward-compatible (default off). The Valves contract test
(`tests/test_valves.py`) must include `audit_log` in the shared core — it is
present on ALL four scripts, so it belongs in `REQUIRED_VALVES`, not in the
cloner-only extras.

## 3. Mechanism

1. **Valve `audit_log: bool = False`** in the four scripts. When off, the
   audit helper is a complete no-op (zero cost, zero logs).
2. **Audit helper in `common.py`** (inline-safe, same style as the rest):
   takes level, action, repo, outcome, and detail; if the Valve is off it
   does nothing; if on, it emits to the existing `"code_explorer"` logger.
   Formats the event with fields: `ts`, `level`, `action`
   (clone/fetch/pull/...), `repo`, `outcome`
   (success/blocked/failed/cancelled/timeout), `detail` (already-normalized
   URL/ref/branch) and `error` (trimmed summary). NEVER writes to stdout or
   via `print`.
   - The helper is async and takes the Valve value from `self.valves` — but
     `common.py` is shared and has no `self`. Signature suggestion:
     `async def audit_event(enabled: bool, level: int, action: str, repo: str,
     outcome: str, detail: str = "", error: str = "")`; the tools pass
     `self.valves.audit_log` as `enabled`. (Alternative: a module-level flag
     set at load — rejected: per-instance Valve injection must be honored.)
3. **Redaction (mandatory):** the error always goes through the existing
   `trim_cause`; raw stderr is never dumped; URLs already carry no
   credentials (`validate_clone_url` rejects them); no code fragment or file
   content is ever logged.
4. **Emission points:** the repos template calls the helper at the event
   points below. The pure validators (`validate_clone_url`, `validate_ref`,
   `resolve_path`) do NOT log themselves: the event is emitted by the caller
   that decides the rejection is an audit event. Logging stays centralized.

## 4. WARNING (30) events — implement

| Event | Emission point |
|---|---|
| Fetch/pull rejected: origin not allow-listed (S1) — a tampered `.git/config` indicator | `_validate_origin` |
| Clone rejected: URL scheme not allowed (`file://`, `ext::`, credentials) | catch in `_clone_repo` when `validate_clone_url` fails |
| Clone rejected: host outside `allowed_hosts` (S3) | `_clone_repo` |
| Invalid ref rejected (revision expressions, options, `..`) | callers of `validate_ref` in the repos tools |
| Invalid path rejected (absolute, `..`, symlink) | callers of `resolve_path` in the repos tools (same pattern extensible to the read tools later) |
| Namespace collision: "repo already exists" (same or different origin) | `_clone_repo` |
| `ref="release"` requested on a repo with no tags | `_clone_repo` (after cloning, when resolving the release) |
| Pull not fast-forwardable or on detached HEAD | `_pull_repo` |
| Fetch or pull timeout (120 s) — non-destructive, retryable | `_fetch_repo` / `_pull_repo` |

## 5. ERROR (40) events — implement

| Event | Emission point |
|---|---|
| Clone failed (network, auth, nonexistent repo) — already cleans up the partial dir | `_clone_repo` |
| **Clone cancelled that left a partial dir** — the most valuable audit event: explains why a namespace is blocked. S4 IS implemented, so the `CancelledError` catch with cleanup is in place; emit here before re-raising | `_clone_repo` (the `except asyncio.CancelledError` blocks) |
| Checkout of the requested ref fails after the clone | `_clone_repo` |
| Fetch failed (network, vanished remote) | `_fetch_repo` |
| Pull failed (conflict, network) | `_pull_repo` |
| Permission error on storage (cannot create/write the directory) | `_clone_repo` |
| Clone timeout (600 s) — worse than fetch: left something half-done | `_clone_repo` |
| Git missing at runtime (distinct from the load-time `check_binaries` warning) | `run_allowed` |

## 6. What is NOT logged

- **Reads and searches** (`cexp_read_file`, `cexp_search_*`, `cexp_list_*`,
  `cexp_show_commit`, `cexp_compare_commits`): read-only, high volume, already
  visible in the chat. Logging them would be noise without audit value.
- **Raw git error content**: only the trimmed summary, never the full stderr.

## 7. CRITICAL (50) — deferred, do NOT implement in this batch

The CRITICAL points are **identified but not implemented now**: broken
security invariants / fail-open, which should only occur from an internal bug
or a tampered environment — a non-allow-listed binary passing validation, a
URL that should have been rejected but was not, a path that escaped the guard,
or the storage root resolving outside the expected area.

**Why deferred:** testing these branches requires fault-injection tests
(simulating a bug in the code itself), of medium cost, and there is no current
evidence a regression could pass unnoticed — the design is already fail-closed
by construction (the guards raise `ToolError` before reaching git).
Implementing CRITICAL without those tests would be decorative dead code.

**Action in this batch:** record in `DESIGN.md` that these points are
identified as future CRITICAL events, without adding the code.

## 8. Tests to add

  the repo).
- Valve on → each case emits the right event with the expected fields: scheme
  rejected (WARNING), origin re-validation (WARNING), invalid ref (WARNING),
  namespace collision (WARNING), release-no-tags (WARNING), fetch timeout
  (WARNING), clone failed (ERROR), fetch/pull failed (ERROR), checkout failed
  (ERROR), clone timeout (ERROR), cancelled clone (ERROR), and successful
  clone/fetch/pull (INFO).
