## 1. Design decision (already made — do not re-litigate)

`cexp_list_files` gains an explicit `recursive: bool = False` parameter.
The default is **non-recursive**: only the direct entries under `path` are
listed (depth 1); subdirectories appear as entries but are not descended
into. `recursive=True` descends (optionally bounded by `max_depth`).

Rationale (recorded in DESIGN.md §10): the old default — unlimited recursion —
filled the `max_results` cap with an alphabetically-truncated deep tree, so a
default listing was both expensive and unpredictable. An explicit flag makes
deep exploration a deliberate agent choice: the default listing is compact,
cheap, and stable; `recursive` is a *selector* in the §6 sense and is applied
identically to the working-tree and `ref` paths.

| # | Decision | Value |
|---|---|---|
| 1 | New parameter | `recursive: bool = False` on `cexp_list_files` |
| 2 | Default | non-recursive: direct entries only |
| 3 | `recursive=True` | unlimited descent (bounded by `max_depth` when given) |
| 4 | `max_depth` without `recursive=True` | explicit `Error:` (no silent semantics) |
| 5 | Applies to | both the working-tree walk (`_list_files`) and the ref listing (`_list_files_at_ref`) |
| 6 | Other parameters | `path`, `filter`, `type`, `ref` unchanged |

Rejected alternative (from an external agent review): `max_depth` alone
implies recursion. Rejected because it keeps an implicit recursion trigger —
the exact ambiguity the flag removes — and gives two ways to express the same
intent. An explicit parameter is clearer for the model.

## 2. Implementation

- `templates/files_search.py.tpl`:
  - `cexp_list_files` public signature gains `recursive: bool = False` after
    `path`; docstring gains a single-line `:param recursive:` (Open WebUI
    parses `:param` lines one at a time, DESIGN.md §9.6) and prose explaining
    the default.
  - `_list_files(...)`: validate `max_depth`/`type` as before; if
    `max_depth is not None and not recursive` → `ToolError("max_depth requires
    recursive=True ...")`; if `not recursive` → `max_depth = 0` (direct
    entries only). The existing `_walk_repo(root, base, max_depth)` already
    implements "dirs at the depth limit are listed but not descended", so no
    walker changes were needed.
  - `_list_files_at_ref(...)`: same validation and the same `max_depth = 0`
    default; the existing depth filter already implements the bound.
  - The public wrapper passes `recursive` through to the impl (fixes the
    missing-argument bug caught during development).
