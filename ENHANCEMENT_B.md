## 1. Design decision (already made — do not re-litigate)

**The directory layout STAYS `<repos_path>/<owner>/<name>` (two levels). The
provider/protocol is NOT part of the path.** It is metadata already persisted
by git itself — `remote.origin.url` in `<repo>/.git/config`, written by the
clone including any `url` override. We do not store anything new: we *read*
the existing origin and *expose* it where the model needs it (the collision
message and `cexp_list_repos`). Namespace collisions are **managed**, not
avoided by re-layout: a second clone attempt for an existing `<owner>/<name>`
returns an informative `Error:` that names the existing origin and tells the
model how to proceed.

| # | Decision | Value |
|---|---|---|
| 1 | `repo` format | `<owner>/<name>`, **unchanged** → zero ripple into read/list/search/commits tools, docstrings, `META_MODEL_PROMPT.md`, README |
| 2 | Provider/protocol storage | git's own `remote.origin.url` (nothing new to persist) |
| 3 | Collision policy | informative `Error:` with existing origin + guidance; no overwrite; no new parameters |
| 4 | Protocol selection | `url` override only, with an **allow-list**; default stays `https://github.com/<owner>/<name>.git`; NO `protocol` parameter, NO provider table |
| 5 | Allowed schemes | `https`, `http`, `git`, `ssh` — everything else rejected |
| 6 | scp-like URLs | `git@github.com:o/r.git` normalized to `ssh://git@github.com/o/r.git` (git's own scp-like semantics) |
| 7 | Credentials in URL | rejected (except the ssh *username*, which is the normal ssh form) — credentials would be persisted in `.git/config` |
| 8 | SSH in headless env | works only with **preconfigured** credentials (`BatchMode=yes`); fails cleanly otherwise; no new Valves |
| 9 | `file://` | **blocked** (local exfiltration); tests migrate to a local `git daemon` fixture (verified working, §5.1) |
| 10 | 3-level `<host>/<owner>/<name>` layout | deferred; only justified if two same-namespace repos from different providers must coexist simultaneously |

Rationale for rejecting the alternatives (recorded for the record):

- **`protocol` parameter** (Option B): the ssh URL form is not universal — the
  ssh user varies per host (`git@`, `deploy@`, ...). Supporting it means adding
  `ssh_user` or assuming a convention, and creates two ways to express the
  same intent (`url` + `protocol` = ambiguity). The `url` override already
  exists and the model knows the pattern.
- **Provider table** (Option C: github→https, gitlab→https, ...): magic that
  does not scale to self-hosted instances and needs maintenance.
- **Keeping `file://` allowed**: it is the only local-exfiltration hole the
  allow-list closes (the model could read any git repo reachable in the
  container, outside `repos_path`). Blocking it and serving tests over
  `git://` is the correct trade-off.
- **Original §12.2 restructure**: rejected for this phase (§1 above). The
  cost (repo format change across every tool, docstring, and prompt example;
  orphaning existing clones; host-regex decisions) is not justified by the
  rare "two same-namespace repos at once" scenario. Reversible later.

### 2.1 `_validate_clone_url(url: str) -> str`

Module-level additions (next to the existing constants/regexes):

```python
from urllib.parse import urlparse

ALLOWED_CLONE_SCHEMES = {"https", "http", "git", "ssh"}
_SCPLIKE_RE = re.compile(r"^([^/@:]+)@([^/:]+):(.+)$")
```

```python
def validate_clone_url(url: str) -> str:
    """Validate and normalize a clone `url` override before it reaches git.

    Protocol allow-list (https/http/git/ssh). Everything else is rejected,
    which closes the RCE gap (`ext::`/`sh::` command URLs) and the local
    exfiltration gap (`file://`), and drops stray protocols (ftp, rsync, ...).
    scp-like "user@host:path" is normalized to ssh://user@host/path exactly
    like git does (no port syntax in scp-like form; use ssh://host:port/path).
    Credentials in the URL are rejected (they would be persisted in
    <repo>/.git/config), except the ssh username (git@github.com is the
    normal ssh form). Returns the normalized URL.
    """
    url = (url or "").strip()
    if not url:
        raise ToolError("invalid clone url: empty")
    if url.startswith("-"):
        raise ToolError(f"invalid clone url: {url!r}", cause="urls may not start with '-'")
    if any(c.isspace() or ord(c) < 32 for c in url):
        raise ToolError(
            f"invalid clone url: {url!r}",
            cause="urls may not contain whitespace or control characters",
        )
    m = _SCPLIKE_RE.match(url)
    if m and "://" not in url:
        user, host, path = m.group(1), m.group(2), m.group(3)
        url = f"ssh://{user}@{host}/{path}"
    parts = urlparse(url)
    scheme = (parts.scheme or "").lower()
    if scheme not in ALLOWED_CLONE_SCHEMES:
        raise ToolError(
            f"invalid clone url: {url!r}",
            cause=f"protocol must be one of {sorted(ALLOWED_CLONE_SCHEMES)}; got {scheme or '(none)'}",
        )
    if parts.query or parts.fragment:
        raise ToolError(
            f"invalid clone url: {url!r}", cause="query strings and fragments are not allowed"
        )
    if scheme == "ssh":
        if parts.password is not None:
            raise ToolError(
                f"invalid clone url: {url!r}", cause="ssh passwords in URLs are not allowed"
            )
    elif parts.username is not None or parts.password is not None:
        raise ToolError(
            f"invalid clone url: {url!r}",
            cause="credentials in URLs are not allowed (they would be persisted in the repo config); use preconfigured credentials instead",
        )
    return url
```

Edge cases covered (each becomes a unit test, §5.2):

- `ext::sh -c 'id'`, `sh::...` → scheme `ext`/`sh` → rejected (RCE vector).
- `file:///etc/passwd`, `file://<anywhere>` → scheme `file` → rejected.
- `ftp://`, `ftps://`, `rsync://`, `s3://`, ... → rejected.
- `-o`, `--upload-pack=...` → leading dash → rejected (pre-existing guard kept).
- `HTTPS://HOST/path` → scheme lowercased → allowed.
- `git@github.com:o/r.git` → normalized to `ssh://git@github.com/o/r.git`.
- `ssh://git@github.com/o/r.git` → allowed as-is.
- `ssh://git:secret@github.com/o/r.git` → password → rejected.
- `https://TOKEN@github.com/o/r.git` or `https://user:pass@...` → rejected.
- `https://github.com/o/r.git?x=1` → query → rejected.
- URLs with whitespace/control chars → rejected.

### 2.2 `_remote_origin(root: str) -> str` (async, tool-side helper)

```python
async def _remote_origin(self, root: str) -> str:
    """The repo's remote origin URL (git remote get-url origin), or '' if
    the clone has no origin (e.g. an initial local-only repo)."""
    res = await run_allowed(git_args("-C", root, "remote", "get-url", "origin"), TIMEOUT_SEARCH)
    if res.returncode != 0:
        return ""  # "No such remote 'origin'" -> rc != 0
    return res.stdout.strip()
```

### 2.3 `_normalize_remote(url: str) -> str` (comparison-only)

Used to decide "same origin" for the collision message. Lowercases
scheme+host, strips a trailing `.git` and trailing `/`, keeps the path case
(git hosting paths are case-sensitive). Not used for anything else.

```python
def _normalize_remote(url: str) -> str:
    url = (url or "").strip()
    if "://" not in url:
        return url
    scheme, rest = url.split("://", 1)
    host, _, path = rest.partition("/")
    path = path.rstrip("/")
    if path.endswith(".git"):
        path = path[:-4]
    return f"{scheme.lower()}://{host.lower()}/{path}"
```

So `https://github.com/o/r` and `https://github.com/o/r.git` compare equal;
`https://github.com/o/r` vs `https://gitlab.com/o/r` compare different.

## 3. `templates/repos.py.tpl` changes

### 3.1 `cexp_clone_repo`

**Order of operations** (security first):

1. `repo = resolve_repo_root(...)` (unchanged).
2. If `url` given → `url = validate_clone_url(url)`; else default
   `remote = f"https://github.com/{repo}.git"` (tool-built, trusted — no
   validation needed). This replaces the current empty/dash-only check
   (repos.py.tpl:82-88).
3. `if root.exists():` → **enriched collision message** (below).
4. Clone, cleanup-on-failure, checkout, JSON — unchanged.

**Collision branch** (replaces repos.py.tpl:73-77):

```python
if root.exists():
    existing = await self._remote_origin(str(root))
    requested = url if url is not None else f"https://github.com/{repo}.git"
    if existing and _normalize_remote(existing) == _normalize_remote(requested):
        raise ToolError(
            f"repo already exists: {repo} at {root} (cloned from {existing}, same origin)",
            cause="use cexp_fetch_repo or cexp_pull_repo to update it (no destructive overwrite)",
        )
    raise ToolError(
        f"repo already exists: {repo} at {root} (cloned from {existing or 'unknown origin'})",
        cause=(
            f"namespace collision: the existing clone comes from a different origin than the "
            f"requested {requested}. One clone per <owner>/<name> is supported; use "
            "cexp_fetch_repo/cexp_pull_repo if it is the same logical repo, or cexp_list_repos "
            "to review existing clones"
        ),
    )
```

Contract preserved: `Error:` prefix (clone did not happen) and the substring
`already exists` — the existing test `test_clone_existing_fails_without_overwrite`
keeps passing (it asserts `startswith("Error:")` + `"already exists"` + no
overwrite).

**Docstring updates** (prose before the first `:param`; each `:param` on a
single line per §9.6):

- State the protocol rules: allowed schemes, scp-like accepted, credentials
  rejected, ssh needs preconfigured credentials (`BatchMode=yes` fails cleanly
  otherwise).
- State the collision behavior: existing origin reported; same origin →
  fetch/pull, different origin → namespace collision, one clone per
  `<owner>/<name>`.

Single-line `:param url:` example:

```
:param url: Optional full clone URL; overrides the default https://github.com/<owner>/<name>.git; protocols https, http, git, ssh are allowed (scp-like git@host:path works); credentials in the URL are rejected; ssh requires preconfigured credentials.
```

## 4. Security posture

| Scheme | Status | Rationale |
|---|---|---|
| `https` | ✅ allowed | default; works everywhere incl. self-hosted with TLS |
| `http` | ✅ allowed | intranet/self-hosted without TLS; documented as plaintext |
| `git` | ✅ allowed | local mirrors, `git daemon` (also the test fixture protocol) |
| `ssh` | ✅ allowed | private repos via preconfigured credentials only |
| `ext::` / `sh::` | ❌ blocked | git's command-execution URL form — the RCE vector |
| `file://` | ❌ blocked | local exfiltration: reads any git repo reachable in the container, outside `repos_path` |
| `ftp`, `ftps`, `rsync`, `s3`, ... | ❌ blocked | stray protocols |
| userinfo (http/https/git) | ❌ blocked | credentials would be persisted in `<repo>/.git/config` on the volume |
| ssh password | ❌ blocked | same reason; ssh *username* is allowed (normal form) |

**Unchanged guarantees** (design already in place, §9.7): only `git` on the
subprocess allow-list, argument arrays, headless env with
`GIT_SSH_COMMAND="ssh -o BatchMode=yes"`, no shell, no network from the
model, no new Valves. ssh clones that lack preconfigured keys/agent/config
fail immediately (BatchMode) — the failure must be routed to the `cause:` of
the clone error so the model understands "missing credential", not "bad url".

## 5. Tests

### 5.1 Fixture: local `git daemon` (verified)

**Verified facts** (tested locally against git 2.x in this repo):

- `git daemon --reuseaddr --base-path=<dir> --export-all --listen=127.0.0.1
  --port=<p>` serves **non-bare** repos (working-tree repos) directly —
  no `git-daemon-export-ok` markers, no bare mirror needed.
- All branches are served (`origin/dev`, `origin/main`, ...) and the daemon
  reads **live** state: mutations to the served repo after the daemon starts
  (e.g. creating a `dev` branch for `test_clone_with_ref_branch`) are visible
  to subsequent clones — no push step required.
- Clone URL is `git://127.0.0.1:<port>/<dirname>` where `<dirname>` is the
  exact directory name under the base path (no `.git` suffix appended;
  requesting `name.git` maps to a directory literally named `name.git`).
- `--export-all` is required (without it, repos are refused).

**Fixture design** (in `conftest.py`, shared by all four test files):

```python
@pytest.fixture(scope="session")
def git_daemon(tmp_path_factory):
    base = tmp_path_factory.mktemp("daemon")
    with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as s:
        s.bind(("127.0.0.1", 0))
        port = s.getsockname()[1]  # reserve a free port, then release
    proc = subprocess.Popen(
        ["git", "daemon", "--reuseaddr", "--export-all",
         f"--base-path={base}", "--listen=127.0.0.1", f"--port={port}"],
        stdout=subprocess.DEVNULL, stderr=subprocess.PIPE,
    )
    deadline = time.time() + 10  # wait until the port accepts connections
    while time.time() < deadline:
        if proc.poll() is not None:
            raise RuntimeError(f"git daemon exited early: {proc.stderr.read()!r}")
        try:
            with socket.create_connection(("127.0.0.1", port), timeout=0.2):
                break
        except OSError:
            time.sleep(0.05)
    yield base, port
    proc.terminate()
    proc.wait(timeout=5)


def daemon_url(base: Path, port: int, name: str) -> str:
    return f"git://127.0.0.1:{port}/{name}"
```

**Migration** (mechanical, all four test files):
